# Участие в разработке BookSharing

Подготовьте базу, сервер и интерфейс по [README](README.md). Примеры запросов находятся в [docs/API.md](docs/API.md).

## Сообщить о проблеме

Создайте [issue](https://github.com/nekronusss/BookSharing/issues) с шагами воспроизведения, ожидаемым и фактическим результатом. Укажите версии Java и Node.js, браузер и способ запуска. Для HTTP-ошибки полезны метод, путь и статус ответа. Не публикуйте JWT, пароли, cookies и личные данные.

## Подготовить изменение

Создайте ветку от `master`. Изменения HTTP-контракта согласуйте между Spring-контроллерами, DTO и `frontend/src/services/api.js`, затем обновите документацию. Для исправления бизнес-логики добавьте тест, проверяющий исходную проблему.

С запущенной отдельной БД и настроенными переменными окружения выполните из корня:

```powershell
.\mvnw.cmd test
.\mvnw.cmd package
cd frontend
npm ci
npm run build
```

В Bash вместо `.\mvnw.cmd` используйте `sh mvnw`. Текущий серверный тест проверяет загрузку контекста; при изменениях обменов дополнительно пройдите сценарий с двумя аккаунтами из README. UI-тесты пока не настроены.

Не добавляйте `uploads/`, `node_modules/`, `target/`, реальные конфиги и секреты в коммиты. При изменении npm-зависимостей обновляйте `frontend/package-lock.json`.

В pull request опишите проблему, новое поведение и результат проверок. Для интерфейса полезны скриншоты на тестовых данных. Если тест или сценарий не запускался, отметьте это явно.

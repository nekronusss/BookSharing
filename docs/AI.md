# BookSharing AI: запуск и сопровождение

AI встроен в существующие BookService/BookRepository, RecommendationService,
JWT и React UI. Ключи никогда не отправляются браузеру. По умолчанию AI выключен.
Обычный каталог, CRUD, оценки и обмены работают независимо от модели.

## Запуск

1. Подготовьте PostgreSQL и JDK 21 по [LOCAL_SETUP.md](LOCAL_SETUP.md).
2. Для существующей базы примените **аддитивную** миграцию:

   ```powershell
   psql -h localhost -U postgres -d booksharing -v ON_ERROR_STOP=1 -f docs/sql/001_ai.sql
   ```

   Для новой локальной базы можно использовать `DDL_AUTO=update`:
   Hibernate создаст в том числе `ai_book_embedding` и `ai_preference`.
   Для production оставьте `DDL_AUTO=validate` и применяйте SQL до запуска
   новой версии приложения. Скрипт повторяемый, не меняет существующие книги.

3. Установите и запустите [Ollama](https://docs.ollama.com/).
   Загрузите модели:

   ```powershell
   ollama pull bge-m3
   ollama pull qwen2.5:7b
   ```

   [BGE-M3](https://ollama.com/library/bge-m3) — многоязычная embedding-модель.
   [Qwen2.5 7B](https://ollama.com/library/qwen2.5:7b) поддерживает русский и
   структурированный вывод. Это базовая конфигурация, а не результат сравнения
   качества на вашем каталоге. Модели можно заменить через окружение.

4. Скопируйте `.env.example` в `.env`, задайте реальные параметры БД/JWT и:

   ```dotenv
   AI_ENABLED=true
   AI_PROVIDER=ollama
   AI_BASE_URL=http://localhost:11434
   AI_API_KEY=
   AI_CHAT_MODEL=qwen2.5:7b
   AI_EMBEDDING_MODEL=bge-m3
   AI_TIMEOUT_SECONDS=120
   ```

   На CPU холодный старт может превышать timeout; предварительно прогрейте
   модели или задайте значение до 120 секунд.

5. Запустите backend с безопасной загрузкой переменных:

   ```powershell
   ./scripts/start-backend.ps1
   ```

   Скрипт читает `KEY=value` как данные, не исполняет содержимое, не печатает
   значения. Spring Boot сам `.env` не загружает. При запуске JAR, в Linux,
   IDE, контейнере или systemd передайте эти же переменные в окружение процесса.
   `AI_*` не должны иметь префикс `VITE_`.

6. Запустите frontend:

   ```powershell
   cd frontend
   npm.cmd ci
   npm.cmd run dev
   ```

   Откройте `http://localhost:4200/?demo=0`. В деморежиме AI честно обозначен
   как недоступный; localStorage-каталог не отправляется реальному серверу.

### Совместимый API

Для сервера, поддерживающего `/embeddings`, `/chat/completions`,
`response_format: {"type":"json_object"}` и `max_tokens`:

```dotenv
AI_PROVIDER=openai-compatible
AI_BASE_URL=https://your-provider.example/v1
AI_API_KEY=replace-locally
AI_CHAT_MODEL=your-chat-model
AI_EMBEDDING_MODEL=your-multilingual-embedding-model
```

Base URL должен включать `/v1`, если провайдер использует этот префикс.
Совместимость конкретного поставщика необходимо проверить: некоторые модели
имеют другой контракт параметров. Native Ollama использует `/api/embed` и
`/api/chat`, без `/v1`. Требуется dense vector из 1–8192 конечных чисел с
ненулевой нормой; неправильный ответ не сохраняется.

### Локальная portable-установка в Windows

Для этого проекта доступны скрипты установки официального Ollama v0.40.6 с
проверкой SHA-256. Бинарные файлы и модели находятся в `.local/ollama/`;
каталог исключён из Git и не удаляется при `mvn clean`.

```powershell
./scripts/install-ollama.ps1
# В отдельном терминале, пока работает приложение:
./scripts/start-ollama.ps1
# В другом терминале:
./.local/ollama/bin/ollama.exe pull bge-m3
./.local/ollama/bin/ollama.exe pull qwen2.5:7b
./.local/ollama/bin/ollama.exe list
```

Сервер слушает только `127.0.0.1:11434`, держит одну модель одновременно и
хранит модели в `.local/ollama/models`. Установка не меняет системный PATH
и не добавляет автозапуск. После перезагрузки запустите `start-ollama.ps1`.

Для отдельной постоянной локальной базы на Windows с установленным PostgreSQL
18 есть `scripts/setup-local-ai.ps1`. Однократный запуск создаёт кластер в
`.local/postgres`, базу `booksharing_ai_local` на порту 55440 и `.env` со
случайными паролем БД/JWT-секретом, включённым Ollama и timeout 120 секунд.
Существующие `.env` или каталог БД скрипт не перезаписывает. Эта база пустая:
зарегистрируйтесь и добавьте свои книги либо выполните `node scripts/seed-catalog.mjs`.
Этот явный импорт создаёт 24 стартовые карточки; тестовые фикстуры в неё не импортируются.

После перезагрузки для этого варианта:

```powershell
& 'C:/Program Files/PostgreSQL/18/bin/pg_ctl.exe' -D .local/postgres -l .local/postgres.log -o '-h 127.0.0.1 -p 55440' -w start
./scripts/start-ollama.ps1
# В другом терминале, после сборки ./mvnw.cmd -DskipTests package:
./scripts/start-backend.ps1 -Packaged
# В третьем терминале:
cd frontend
npm.cmd run dev -- --host 127.0.0.1
```

Откройте `http://127.0.0.1:4200/?demo=0`. Для остановки завершите backend,
frontend и Ollama через Ctrl+C в соответствующих терминалах, затем остановите
локальную БД: `pg_ctl -D .local/postgres -m fast -w stop` (из PostgreSQL bin).
Файлы `.env` и `.local/` исключены из Git. Сохраняйте их при переносе локальных
данных; для production используйте отдельную управляемую БД и миграции.

## Возможности и API

Внешний URL через frontend начинается с `/api`, например `/api/ai/search`.
Ниже перечислены пути непосредственно Spring Boot.

| Метод и путь | Доступ | Тело / результат |
| --- | --- | --- |
| GET `/ai/status` | Публичный | `{enabled}`: конфигурация, не health check модели |
| POST `/ai/search` | Публичный | `{query, category?}` → `{items, mode, notice}` |
| GET `/ai/books/{id}/similar` | Публичный | До 4 похожих книг; закрытый источник → 404 |
| GET `/ai/recommendations` | JWT | До 4 персональных рекомендаций |
| GET `/ai/preferences` | JWT | Предпочтения текущего пользователя |
| PUT `/ai/preferences` | JWT | `{genres:[], interests:"", useHistory:false}` |
| POST `/ai/chat` | JWT | `{message, history:[], usePreferences:false}` |
| POST `/ai/books/description-suggestion` | JWT | `{title, author, description, category?, tags:[]}` |

`items` содержат `{book: BookDto, relevance, explanation}`. `relevance` — оценка
ранжирования, **не вероятность** и не процент совместимости. UI её не показывает.
Поиск возвращает до 24 наиболее релевантных результатов, сортировка по
релевантности; обычная пагинация остаётся в обычном поиске.

Режимы: `hybrid`, `keyword`, `content`, `personalized`, `grounded`, `retrieval`.
Сообщение `notice` объясняет fallback/неполный индекс. Недоступный LLM в чате
оставляет проверенные результаты retrieval; description возвращает 503.
Ошибки используют общий формат `{code,message,timestamp}`, Bean Validation —
существующий формат `errors`. Лимит — 429 с `Retry-After: 60`.

Поиск принимает 1000 символов. Чат — 1000 символов плюс максимум 4 предыдущих
пользовательских сообщения по 1000 символов. Ответы ассистента не принимаются
как история от клиента. В браузере остаётся максимум 20 сообщений; очистка и
уход со страницы удаляют диалог. В БД чат не сохраняется.

В описание нужно ввести реальные сведения. AI редактирует их, предлагает теги
и категорию. Результат — черновик, затем «Применить черновик к форме», затем
обычное сохранение. Изменение исходных полей делает старый черновик неприменимым.
LLM может ошибаться при перефразировании, поэтому проверка фактов владельцем
остаётся обязательной частью интерфейса.

## Индекс и доступность

Текст: название, автор, категория, теги, описание. Индекс содержит JSON dense
vector, SHA-256 текста и SHA-256 идентичности endpoint/provider/model/версии
представления. Счётчики просмотров не вызывают переиндексацию.

При включённом AI планировщик начинает обход через 5 секунд, берёт до 16 книг
за проход, затем ждёт 30 секунд и продолжает с последнего ID. После конца
возвращается к началу. Новые и изменённые книги индексируются **асинхронно**.
Ошибка одной книги не останавливает навсегда обход других; повторная попытка
будет на следующем полном проходе. Ошибки модели не отменяют создание книги.
Размер порции и интервал задаются `AI_INDEX_BATCH_SIZE`, `AI_INDEX_DELAY_MS`.

При каждом retrieval сравниваются хеши. Устаревшие и полученные другой моделью
векторы игнорируются; до обновления книга ищется по тексту. При удалении книги
PostgreSQL удаляет вектор через FK `ON DELETE CASCADE`. Закрытые книги и полки
не индексируются; существующий вектор скрытой книги не используется и не
передаётся модели. Он может оставаться в БД до удаления книги.

Публичные результаты требуют `isPublic=true` и `privateBooks=false`.
Книги в ACCEPTED, WAITING_FOR_SHIPMENT, IN_TRANSIT, DELIVERED исключаются как
запрошенные, так и предложенные. PENDING не резервирует книгу.
После генерации чат повторно проверяет доступность и основные метаданные.
Модель не подтверждает обмен: последнее слово за владельцем и обычным API обменов.

Для запроса «похожие на …» точное упоминание названия публичной книги добавляет
её реальные метаданные в retrieval и исключает сам источник из результатов.
Это работает и для книги, которая сейчас участвует в активной передаче.
Если такой книги нет в каталоге, система не изобретает описание.

## Ранжирование

Search: 0.7 × cosine + 0.3 × lexical. При недоступном embedding API — lexical.
Если словесных совпадений нет, cosine должен быть не меньше
`AI_SIMILARITY_THRESHOLD` (по умолчанию 0.45). Порог нужно калибровать на
выбранной модели и размеченных запросах; он не является оценкой достоверности.

Similar: 0.65 × cosine + 0.2 × lexical + 0.15 за общий жанр. Внешних вызовов нет.

Recommendations: 0.4 за выбранный жанр + 0.25 × совпадение интересов +
0.3 × близость к наиболее похожей книге истории + 0.05 × популярность
(`log1p(likesCount)`, ограниченная сверху). История включается только по
сохранённому `useHistory=true`: оба источника избранного, оценки ≥4,
полученные книги COMPLETED. Оценки ≤2 исключают книгу из позитивных источников;
уже известные и собственные книги исключаются из результатов. При cold start
используются выбранные жанры/интересы, затем популярность. Индивидуальные
просмотры и collaborative filtering не используются.

Личные сигналы обрабатываются локально. В чат они влияют на порядок
кандидатов только при дополнительном согласии `usePreferences=true`.
LLM получает публичные поля книг и сообщения текущего диалога, без usernames,
профилей, паролей, токенов, сообщений обменов или трекинг-номеров.
Он возвращает ID и цитаты; неизвестный ID или неподтверждённая цитата приводит
к безопасному retrieval fallback. Свободный текст модели не отображается как
достоверный ответ о каталоге. Уточнения выбираются из серверных шаблонов.

## pgvector и масштабирование

В установленном локальном PostgreSQL 18 расширение vector не обнаружено.
Использован разрешённый альтернативный механизм: PostgreSQL text JSON + точный
cosine в Java. Это реальные векторы модели, без случайных чисел и хеш-эмбеддингов.
Для небольшого каталога не нужен отдельный vector database.

Стоимость retrieval O(N·d), память O(N·d); каталог загружается целиком после
фильтра прав, поэтому этот вариант не предназначен для сотен тысяч книг.
Следующий шаг при росте: установить [pgvector](https://github.com/pgvector/pgvector),
перенести векторы одной модели в `vector(d)`, использовать cosine `<=>`,
HNSW и фильтры публичности/обменов в SQL до выдачи результатов. Не смешивать
модели/размерности; делать backfill и сравнение recall до переключения.
Текущая реализация не заявляет поддержку HNSW и не создаёт расширение автоматически.

## Лимиты и эксплуатация

- `AI_REQUESTS_PER_MINUTE=12`: общий лимит AI endpoint-запросов на JWT
  пользователя или реальный remote IP. `X-Forwarded-For` не доверяется.
- `AI_DAILY_CALL_BUDGET=1000`: число попыток HTTP к модели на процесс за UTC-день,
  включая индексирование. Это ограничение вызовов, не денежная смета.
- Не более 2 одновременных provider-запросов. Без автоматических HTTP retry.
- Timeout каждого запроса 1–120 секунд; после ошибки транспорта — пауза 30 секунд.
- Генерация ограничена 1200 выходными токенами и 1 МБ ответа.
- Ключи и тела provider-ошибок не логируются и не возвращаются клиенту.

Лимиты находятся в памяти и сбрасываются после рестарта. Для нескольких реплик
используйте общий Redis/gateway, один индексатор/распределённый lock и внешний
лимит расходов провайдера. Длинная генерация не держит транзакцию записи БД.
Стоимость embeddings публичных описаний и обработки запросов зависит от
выбранного поставщика. Удаление/смена модели требует повторной индексации.

## Проверки

Фактические результаты локальной проверки: [AI_VERIFICATION.md](AI_VERIFICATION.md).

Без PostgreSQL и ключей:

```powershell
./mvnw.cmd -Dtest=CoreWorkflowTest,PersonalApiSecurityTest,AiServicesTest,AiProviderTest test
cd frontend
npm.cmd test
npm.cmd run build
npm.cmd run format:check
```

Интеграционные проверки используют только отдельную **удаляемую** БД с именем
`booksharing_ai_test`; Hibernate создаёт и удаляет её таблицы:

```powershell
$env:AI_TEST_DB_URL='jdbc:postgresql://localhost:5432/booksharing_ai_test'
$env:AI_TEST_DB_USERNAME='ai_test'
$env:AI_TEST_DB_PASSWORD='your-test-password'
./mvnw.cmd -Dtest=AiPostgresTest test
```

CI запускает этот набор с PostgreSQL 17. Локально проверяется PostgreSQL 18.
Тесты provider-контракта используют настоящий HTTP к локальному тестовому
серверу; PostgreSQL-тесты подменяют модель для воспроизводимости. Они проверяют
интеграцию и защитные условия, но **не измеряют качество реальной модели**.

Для приёмки с настоящими локальными моделями после их загрузки:

```powershell
$env:AI_LIVE_TEST='true'
# AI_TEST_DB_URL/USERNAME/PASSWORD — как в примере выше; только отдельная тестовая БД.
./mvnw.cmd -Dtest=AiLiveTest test
```

Этот тест реально генерирует embeddings, проверяет смысловой запрос без
точного совпадения названия, похожие книги, персональные предпочтения,
ответ Qwen по каталогу и черновик описания. Он не использует mock-провайдер.
Результаты сохраняются в `target/ai-live-results.json`. Тестовые книги
находятся только в отдельной тестовой БД и удаляются после проверки.

После подключения реального провайдера проведите приёмку:

1. Добавьте публичные книги с содержательными описаниями; дождитесь индекса.
2. Проверьте 5–10 русскоязычных запросов с известными подходящими книгами.
3. Проверьте приватную книгу, закрытую полку и книгу в активном обмене.
4. Измените описание и проверьте обновление; удалите тестовую книгу и её вектор.
5. Выберите жанры на главной, включите/выключите использование истории.
6. Уточните запрос в чате; запросите несуществующую книгу.
7. Сгенерируйте, отклоните и примените черновик; проверьте обычное сохранение.
8. Остановите модель и убедитесь, что каталог и обмены продолжают работать.

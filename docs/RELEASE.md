# Перед публичным запуском

Интерфейс, автономное демо и AI-функции проверены локально. Сервер пока следует использовать в локальной/тестовой среде. Результаты PostgreSQL-, JWT- и Ollama-проверок: [AI_VERIFICATION.md](AI_VERIFICATION.md).

Исправлены: отсутствие PUT для книги, валидация multipart-данных книги и профиля, отсутствие QR у новых книг, доступ посторонних к деталям обмена, повторное отображение уже выполненного подтверждения, поиск автора, приватность книг в основных запросах каталога, небезопасные имена загружаемых файлов, отдача внутренних ошибок и секреты в основной конфигурации. Изображения декодируются, ограничиваются по размеру и разрешению, затем кодируются заново.

Дополнительно закрыт доступ к чужим уведомлениям, событиям и шаблонам: действующий пользователь берётся из контекста аутентификации, права проверяются до изменения данных. Пакет отметки уведомлений проверяется целиком и ограничен 100 ID. События и шаблоны возвращают DTO без вложенных сущностей пользователей и книг. Создание книги из шаблона использует валидируемые поля обычного создания книги; идентификаторы, связи, URL файлов и счётчики из JSON не переносятся. Добавлены 45 HTTP-тестов контроллеров, они и 4 существующих теста проходят на Java 21 и включены в CI. Это проверки с mock-репозиториями, а не проверка JWT-фильтра или интеграция с PostgreSQL. Изменения контрактов описаны в [PERSONAL_API.md](PERSONAL_API.md).

Осталось до публичного запуска:

- AI-интеграционные тесты с PostgreSQL, настоящим JWT и повторяемой AI-миграцией пройдены. Остаются миграции всей исторической схемы (Flyway/Liquibase), индексы и проверка совместимости старых данных на копии production-базы.
- Обеспечить блокировки/версионирование обменов: текущий сервер не гарантирует защиту от одновременного принятия конкурирующих заявок и одновременных подтверждений. Демосценарий проверяет резервацию последовательно, но не моделирует транзакции БД.
- Продолжить аудит старых дополнительных API (messages, achievements, user lists и других). В них остаются операции с переданным клиентом userId; исправления events/templates/notifications не распространяются на эти маршруты. Проверить весь путь аутентификации и авторизации с настоящим JWT и PostgreSQL, включая откат транзакций и границы дат событий; добавить пагинацию личных коллекций.
- Проверить приватность во всех дополнительных API и доступ к файлам: uploads пока обслуживается публично. Скрытие карточки не делает известный адрес обложки секретным.
- Добавить ограничение частоты входа/регистрации, восстановление доступа и выбранный механизм управления сессиями. JWT сейчас используется через localStorage; необходим отдельный анализ угроз перед публичным запуском.
- Решить продуктовый сценарий связи после заявки: в этой версии есть сообщение при создании заявки, но нет приватного чата, проверенной доставки уведомлений или поддержки пользователей.
- Подготовить мониторинг, структурированные журналы, резервные копии БД и uploads, восстановление, HTTPS, политику хранения данных и эксплуатационные процедуры.
- Проверить адаптивную вёрстку и камеру в реальных мобильных и настольных браузерах. В текущей сессии подключённый браузер отсутствовал; тесты компонентов не проверяют пиксельный результат.
- Сверить npm audit и зависимости Maven перед релизом. Не применять major-обновления автоматически без проверки совместимости.

Frontend переведён на Vite 7, Tailwind 4 и React Router 7. На 21 октября 2026 года `npm audit --audit-level=moderate` сообщает 0 уязвимостей; тесты и сборка проходят. CI включает npm audit и отдельную PostgreSQL-проверку AI. Это не заменяет аудит бизнес-логики и всего серверного dependency tree.

Файл .env.example содержит только образцы. Старый JWT-секрет и пароль были ранее записаны в репозитории: для реального окружения нужны новые значения, а при наличии живого развёртывания — ротация.

# Уведомления, события и шаблоны

Все маршруты требуют аутентификацию. Действующий пользователь определяется сервером из контекста Spring Security. Поля `userId`/`user_id` оставлены для совместимости и необязательны: свой ID принимается, чужой возвращает `403`. Они не выбирают владельца новой записи. Отсутствие аутентификации или удалённый пользователь дают `401`.

Адреса ниже — маршруты Spring Boot. При обращении через Vite добавьте `/api`: прокси удаляет этот префикс.

## Уведомления

- `GET /notifications` возвращает только уведомления текущего пользователя. Старый серверный маршрут `/api/notifications` тоже поддерживается.
- `POST /notifications/mark_read` принимает JSON-массив из 1–100 положительных ID, например `[10, 11]`. Старый маршрут `/api/notifications/mark_read` сохранён.
- Перед изменением проверяется весь пакет. Если хотя бы один ID отсутствует или принадлежит другому пользователю, ответ — `404`, ни одно уведомление пакета не изменяется. Сохранение выполняется в одной транзакции.
- Повторяющиеся ID и повторная отметка своих уведомлений допустимы. Пустой пакет, `null`, отрицательные ID и превышение лимита дают `400`.

## События

- `GET /events?date=2026-10-19` возвращает события текущего пользователя за календарный день: от полуночи включительно до следующей полуночи исключительно. Порядок — время, затем ID. Используется локальное время без часового пояса, как в существующей модели.
- `POST /events` принимает `bookId`, `title`, `description`, `priority`, `dateTime`; `userId` необязателен. Обязательны положительный `bookId`, непустой заголовок до 255 символов и дата/время ISO, например `2026-10-19T12:00:00`. Описание — до 255 символов, в соответствии с текущим столбцом БД.
- Книга должна быть доступна текущему пользователю: собственная либо публичная у владельца с открытыми книгами. Недоступная книга возвращает `404`.
- `PUT /events/{id}` меняет только заголовок, описание, приоритет и дату/время собственного события. Владелец и книга не меняются; другой `bookId` даёт `400`.
- `DELETE /events/{id}` удаляет только собственное событие. Чужое или отсутствующее событие для изменения/удаления возвращает одинаковый `404`.

Ответ события содержит `id`, `title`, `description`, `priority`, `dateTime`, `userId`, `bookId`. **Вместо вложенных `user` и `book` теперь возвращаются только их ID**: email, список лайкнувших и содержимое скрытой книги не сериализуются.

## Шаблоны

- `GET /templates` возвращает только собственные шаблоны.
- `POST /templates` принимает `name` (непустое, до 255 символов), `data` (строка JSON до 20 000 символов) и необязательный `userId`.
- JSON в `data` должен соответствовать обычному запросу создания книги: обязательны `title`, `author`, `year`; также допустимы `description`, `tags`, `category`, `isPublic`. Применяются ограничения `CreateBookRequest`. Старое имя `public` также принимается и сохраняет настройку приватности.
- Посторонние поля (`id`, `user`, `likedUsers`, `qrCode`, URL, рейтинги и счётчики) отбрасываются. При сохранении остаются только разрешённые поля.
- `POST /templates/from_template/{templateId}` создаёт книгу из собственного шаблона через `BookService`. Тело можно не передавать; старое тело `{"userId": 1}` поддерживается только для своего ID. Новый владелец и QR определяются сервером.
- Чужой или отсутствующий шаблон даёт `404`. Старые шаблоны проверяются повторно при использовании; некорректный JSON или отсутствие обязательных полей дают `400`, книгу не создают.

Ответ шаблона содержит `id`, `name`, `data`, `userId` вместо вложенного `user`. Создание книги из шаблона возвращает **`BookDto`**, как обычное создание книги, вместо JPA-сущности `Book`. Текущий React-интерфейс эти дополнительные API не использует; внешние клиенты должны учитывать изменения формата ответа.

## Проверки и ограничения

```powershell
./mvnw.cmd '-Dtest=CoreWorkflowTest,PersonalApiSecurityTest' test
```

Нужен JDK 21. Тесты проверяют HTTP-привязку параметров, Bean Validation, выбор текущего пользователя, права владения, пакетную проверку уведомлений и создание книги из недоверенного шаблона. Репозитории подменены mock-объектами; PostgreSQL не требуется. JWT-фильтр, реальные транзакции, JPQL-запрос по датам и конкурентные запросы требуют отдельных интеграционных проверок перед релизом. Схема БД в этом изменении не меняется.

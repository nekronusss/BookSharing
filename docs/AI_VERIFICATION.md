## Проверка настоящих моделей

Сквозной тест создал пять публичных книг и одну приватную в тестовой БД,
построил настоящие embeddings и выполнил запросы через Spring MVC и JWT.

- «Хочу научиться писать программы с нуля»: первым найден учебник Python,
  режим ответа — `hybrid`.
- Для «1984» первой похожей книгой стал «О дивный новый мир».
- Предпочтения «Наука» и «программирование» вывели учебник Python первым.
- Чат вернул `grounded` с реальным ID книги и дословным фрагментом её описания.
- Черновик описания сохранил сведения о царапине на обложке и не сохранил
  изменения в каталог. После обнаруженного пропуска состояния экземпляра
  инструкция модели усилена, а этот случай закреплён в сквозном тесте.
- Приватная книга не получила embedding и не попала в выдачу.

Подробные ответы: `target/ai-live-results.json`; логи:
`target/ai-live-verification.log`, `target/ai-verification.log`,
`target/ai-package.log`. Это локальные артефакты, не файлы для публикации.

## Границы проверки

Небольшой тестовый каталог подтверждает работоспособность интеграции, но не
заменяет оценку качества рекомендаций на пользовательском каталоге.
OpenAI-compatible контракт проверен локальным HTTP-сервером; внешняя платная
модель не вызывалась. Браузер для визуальной проверки не был доступен:
интерфейс проверен React-тестами и сборкой, без визуальной приёмки.

Векторы хранятся в PostgreSQL без обязательного расширения pgvector;
косинусное ранжирование выполняется в Java. Это документированный вариант
для небольшого каталога. Для большого каталога предусмотрен путь перехода
к pgvector, но HNSW-индекс в этой реализации не создаётся.

Запуск локальный; публикация приложения в production не выполнялась.
Лимиты запросов и бюджета действуют на один процесс.
Сгенерированное описание всегда требует проверки и подтверждения владельца.

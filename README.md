# BookSharing

Русскоязычный сервис обмена бумажными книгами. React 18 + Vite + Tailwind на клиенте, Java 21 + Spring Boot 3 + PostgreSQL на сервере.

## Быстрая демонстрация

```powershell
cd frontend
npm ci
npm run dev
```

Откройте **http://localhost:4200/?demo=1**. PostgreSQL и Java для демонстрации не нужны.

В верхней полосе нажмите **«Войти как Алина»**. Доступны два персонажа: **alina** и **mark**, пароль для обоих — **demo123**. Не используйте настоящие пароли в демо. Можно переключаться между участниками, а кнопка «Сбросить демо» возвращает исходные данные.

Демо содержит 16 книг, избранное, комментарии и входящую заявку. Сценарии добавления и редактирования книги, поиска, профиля, QR-поиска и обмена сохраняются в localStorage этого браузера. Они не отправляют изменения в Spring Boot. Обложки в демо ограничены 2 МБ из-за квоты localStorage. Деморежим явно обозначен; ошибки реального сервера никогда не подменяются вымышленными результатами.

## Что можно показать

- Адаптивные главная и каталог с авторской книжной иллюстрацией, жанрами, сортировкой, поиском по названию и автору, пагинацией.
- Карточка книги с обложкой, оценками, избранным, комментариями и QR-паспортом.
- Личная полка, настройка профиля, создание и редактирование книги с предпросмотром обложки.
- Входящие и исходящие заявки; принятие, отправка, доставка, подтверждение обеими сторонами и смена владельцев.
- QR-сканер с камерой и ручным вводом. Демо-код: `BOOK-DEMO-1`.
- Состояния загрузки, пустого каталога, ошибок, неизвестного адреса; диалоги с фокусом и управлением с клавиатуры.

Это **обмен/дарение с передачей собственности**, а не аренда. QR-код открывает карточку и не подтверждает обмен.

Пошаговый показ: [docs/DEMO.md](docs/DEMO.md).

## Реальный API

Отключите демо кнопкой «К реальному API» или откройте `/?demo=0`.

Нужны JDK 21 и PostgreSQL с базой `booksharing`. Переменные перечислены в [.env.example](.env.example). Spring Boot не читает этот файл автоматически: задайте переменные в терминале или настройках запуска IDE.

```powershell
$env:DB_URL = 'jdbc:postgresql://localhost:5432/booksharing'
$env:DB_USERNAME = 'postgres'
$env:DB_PASSWORD = '<пароль вашей локальной БД>'
$env:JWT_SECRET = '<случайный секрет длиной не менее 32 байт>'
$env:DDL_AUTO = 'update' # только локальная база разработки
./mvnw.cmd spring-boot:run
```

Сервер слушает порт 8080. Клиент по умолчанию использует `/api`; Vite перенаправляет его на `localhost:8080` без префикса. Переменная `VITE_API_URL` позволяет задать другой адрес при сборке. Уже существующий локальный `frontend/.env` имеет приоритет.

Без `DDL_AUTO=update` сервер проверяет схему (`validate`) и не меняет её автоматически. Для существующей базы изменение длины `book.description` до 5000 символов необходимо применить явно. Версионированные миграции ещё не подготовлены.

## Проверки

```powershell
cd frontend
npm test
npm run format:check
npm run build
npm run preview
```

`npm test` проверяет сценарии демо и React-компоненты через react-test-renderer. Это не замена проверке в настоящем браузере и не тесты пиксельной вёрстки.

Из корня проекта:

```powershell
./mvnw.cmd '-Dtest=CoreWorkflowTest,PersonalApiSecurityTest' test
```

Модульные тесты Java проверяют приватность обмена, подтверждение обеих сторон, права на редактирование и генерацию QR. `PersonalApiSecurityTest` проверяет через MockMvc доступ к уведомлениям, событиям и шаблонам, валидацию запросов и защиту от подмены владельца. Эти проверки работают без БД и не проверяют JWT-фильтр или реальные транзакции PostgreSQL. Полный `./mvnw.cmd test` также запускает существующий `@SpringBootTest` и требует настроенную PostgreSQL. Контракты исправленных API: [docs/PERSONAL_API.md](docs/PERSONAL_API.md).

## Сборка демонстрации в контейнер

```powershell
docker build -t booksharing-demo ./frontend
docker run --rm -p 4200:8080 booksharing-demo
```

Откройте `http://localhost:4200/?demo=1`. Контейнер обслуживает статический клиент; API в него не входит. Для подключения API на хосте задайте `--build-arg VITE_API_URL=https://api.example.org` при сборке и настройте CORS на сервере.

## Границы готовности

По выбранному приоритету подготовлены интерфейс и автономная демонстрация. Это **не аттестация готовности сервера к публичному продакшену**. Не выполнены развёртывание с реальной PostgreSQL, сквозная проверка на сервере, нагрузочные испытания и визуальная проверка в подключённом браузере. Список задач для реального запуска: [docs/RELEASE.md](docs/RELEASE.md).

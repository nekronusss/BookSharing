# BookSharing AI

Русскоязычная платформа обмена бумажными книгами с поиском по смыслу,
персональными рекомендациями и книжным AI-помощником.
React 18, Java 21, Spring Boot 3 и PostgreSQL; модели запускаются локально
через Ollama или подключаются через OpenAI-compatible API.

## Возможности

| Возможность | Как работает |
| --- | --- |
| Каталог и личная полка | Книги, категории, теги, обложки, поиск, оценки, избранное и комментарии |
| Обмены | Заявка, принятие, отправка, доставка и подтверждение обеими сторонами; передача собственности |
| QR-паспорт | Открывает карточку книги; сам по себе не подтверждает обмен |
| AI-поиск | Например, «грустная философская книга об одиночестве»; сочетает embeddings и совпадения слов |
| Персональный подбор | Жанры и интересы; с согласия пользователя — избранное, оценки и завершённые обмены |
| AI-помощник | Диалог на русском с ограниченной историей, реальными карточками и проверяемыми цитатами |
| Похожие книги | Общий индекс embeddings; без отдельного LLM-запроса на каждое открытие |
| Черновик описания | Улучшение введённого текста, теги и категория; применение и сохранение только пользователем |

AI получает публичные книжные данные. Закрытые книги и книги в активной
передаче исключаются из AI-выдачи. Если модель недоступна, обычный каталог
продолжает работать, а поиск явно сообщает о переходе к поиску по словам.

## Быстрый запуск полного приложения

Нужны JDK 21, PostgreSQL, Node.js 22.12+ в ветке 22 или Node.js 24, npm и Ollama.
Команды ниже даны для PowerShell; в Bash используйте `sh mvnw` вместо
`./mvnw.cmd` и передавайте переменные окружения средствами своей оболочки.

### 1. База и конфигурация

Создайте отдельную локальную базу `booksharing`. Скопируйте
[.env.example](.env.example) в `.env` и задайте параметры подключения:

```dotenv
DB_URL=jdbc:postgresql://localhost:5432/booksharing
DB_USERNAME=postgres
DB_PASSWORD=your-local-password
JWT_SECRET=replace-with-a-random-secret-of-at-least-32-bytes
DDL_AUTO=update
AI_ENABLED=true
AI_PROVIDER=ollama
AI_BASE_URL=http://127.0.0.1:11434
AI_CHAT_MODEL=qwen2.5:7b
AI_EMBEDDING_MODEL=bge-m3
AI_TIMEOUT_SECONDS=120
```

`DDL_AUTO=update` предназначен для новой локальной базы. Для существующей
базы примените [AI-миграцию](docs/sql/001_ai.sql); в production используется
`validate` и отдельная процедура миграций. Перед изменениями существующей
базы сделайте резервную копию. Остальная настройка PostgreSQL описана в
[LOCAL_SETUP.md](docs/LOCAL_SETUP.md).

### 2. Модели

Запустите Ollama, затем загрузите модели — суммарно около 6 ГБ:

```powershell
ollama pull bge-m3
ollama pull qwen2.5:7b
```

В Windows можно установить изолированный Ollama в `.local/ollama`:

```powershell
./scripts/install-ollama.ps1
./scripts/start-ollama.ps1
# В другом терминале:
./.local/ollama/bin/ollama.exe pull bge-m3
./.local/ollama/bin/ollama.exe pull qwen2.5:7b
```

Этот вариант хранит модели внутри проекта и не добавляет сервер в автозапуск.
Холодный старт модели может занять заметное время. Параметры провайдера,
лимиты и подключение внешнего API описаны в [AI.md](docs/AI.md).

### 3. Backend

```powershell
./scripts/start-backend.ps1
```

Скрипт загружает `.env` как данные и запускает Spring Boot на порту 8080.
Spring Boot сам `.env` не читает. Для запуска собранного приложения:

```powershell
./mvnw.cmd -DskipTests package
./scripts/start-backend.ps1 -Packaged
```

### 4. Наполнение каталога

При работающем backend выполните из корня:

```powershell
node scripts/seed-catalog.mjs
```

В PostgreSQL через обычный REST API добавятся **24 книги**: антиутопии,
фэнтези, классика, детективы, психология, научно-популярные и детские книги,
учебник Python. Повторный запуск пропускает уже имеющиеся пары «название +
автор» и не меняет чужие записи. Создаются настоящие записи приложения,
которые автоматически индексируются для AI-поиска.

Это стартовые библиографические карточки, а не подтверждение наличия бумажных
экземпляров: соответствующая пометка есть в каждом описании. Год относится
к ранней публикации произведения (пояснения — в документе о каталоге);
состояние и конкретное издание не выдумываются.
Рейтинги, лайки и история обменов не накручиваются. Обложки отображаются
встроенным типографическим компонентом, без скачивания чужих изображений.

Владелец стартовой полки создаётся со случайным паролем. Данные входа находятся
в `.local/starter-account-8080.json`, исключённом из Git; пароль не печатается
в консоль. Для персонального подбора зарегистрируйте отдельного читателя:
собственные книги владельцу не рекомендуются. Состав и пояснения:
[data/starter-books.json](data/starter-books.json), [STARTER_CATALOG.md](docs/STARTER_CATALOG.md).

### 5. Frontend

```powershell
cd frontend
npm ci
npm run dev
```

Откройте **http://127.0.0.1:4200/?demo=0**. Vite проксирует `/api` в
`http://127.0.0.1:8080`. Зарегистрируйтесь, выберите жанры на главной и
попробуйте AI-поиск. Индексация выполняется в фоне порциями по 16 книг;
после импорта дайте модели время обработать новые записи.

Для Windows с установленным PostgreSQL 18 также есть однократный
`./scripts/setup-local-ai.ps1`: он создаёт отдельную базу на порту 55440 и
`.env` со случайными секретами. Запускайте его **вместо ручного создания**
конфигурации: существующие `.env` и локальный кластер он не перезаписывает.
Команды повторного запуска и остановки — в [AI.md](docs/AI.md).

## Деморежим без сервера

Для знакомства с интерфейсом достаточно `npm ci` и `npm run dev` в `frontend`.
Откройте `http://localhost:4200/?demo=1` и нажмите «Войти как Алина».
Демо-аккаунты: `alina` и `mark`, пароль `demo123`; настоящие пароли здесь не нужны.

Демо хранит 16 отдельных книг и изменения в localStorage. Оно не связано
с PostgreSQL и не отправляет данные в AI: AI-функции явно недоступны.
Пошаговый показ — [DEMO.md](docs/DEMO.md).

## Архитектура и API

```text
React → Spring REST API / JWT → AI application services
                                  ├─ BookRepository / PostgreSQL
                                  ├─ embedding index / ranking
                                  └─ AiProvider → Ollama / compatible API
```

Для небольшого каталога векторы хранятся в PostgreSQL, а точное косинусное
ранжирование выполняется в Java. pgvector не является обязательным расширением;
обоснование и путь масштабирования описаны в [архитектурном плане](docs/AI_IMPLEMENTATION_PLAN.md).
API-ключи доступны только backend. Действуют тайм-ауты, валидация, ограничения
длины запросов, частоты вызовов и дневного бюджета.

| API backend | Назначение | Доступ |
| --- | --- | --- |
| `POST /ai/search` | Гибридный поиск | Публичный |
| `GET /ai/books/{id}/similar` | Похожие книги | Публичный |
| `GET /ai/recommendations` | Персональные рекомендации | JWT |
| `GET/PUT /ai/preferences` | Жанры, интересы, согласие на историю | JWT |
| `POST /ai/chat` | Диалог с карточками | JWT |
| `POST /ai/books/description-suggestion` | Черновик без сохранения | JWT |

Через Vite к путям добавляется `/api`. DTO и эксплуатационные ограничения:
[AI.md](docs/AI.md). Основные API: [API.md](docs/API.md),
личные ресурсы: [PERSONAL_API.md](docs/PERSONAL_API.md).

## Проверки

```powershell
# Без PostgreSQL и AI-моделей:
./mvnw.cmd '-Dtest=CoreWorkflowTest,PersonalApiSecurityTest,AiServicesTest,AiProviderTest' test

cd frontend
npm test
npm run format:check
npm run build
```

Тесты `AiPostgresTest` и `AiLiveTest` используют отдельную удаляемую базу
`booksharing_ai_test`. Не направляйте их на рабочие данные.
Команды запуска с PostgreSQL и настоящим Ollama приведены в [AI.md](docs/AI.md).

Проверено локально: **67 backend-тестов, 1 сквозной тест всех пяти AI-функций
с настоящими моделями, 16 frontend-тестов, сборки JAR и Vite**.
Подробности и границы проверки: [AI_VERIFICATION.md](docs/AI_VERIFICATION.md).
Визуальная приёмка в браузере и нагрузочные испытания не выполнены.

## Развёртывание и участие

Локальная работа с PostgreSQL и Ollama проверена. Перед публичным запуском
нужны HTTPS, резервное копирование, управление секретами и миграциями,
мониторинг и оценка нагрузки. Лимиты AI сейчас рассчитаны на один процесс;
нескольким репликам нужен общий механизм ограничений. Checklist:
[RELEASE.md](docs/RELEASE.md).

Frontend можно собрать отдельно через `docker build -t booksharing-ui ./frontend`.
Этот контейнер обслуживает только статический клиент; backend, PostgreSQL,
Ollama и reverse proxy разворачиваются отдельно. Для другого API задайте
`VITE_API_URL` при сборке и разрешённые CORS origins на сервере.

Правила участия: [CONTRIBUTING.md](CONTRIBUTING.md).
Бинарные файлы моделей, `.env`, `.local/`, `uploads/`, `target/` и
`node_modules/` не включаются в Git.
